# 看板實戰 筆記
書名 :    
看板實戰：用一張便利貼訓練出100分高效率工作團隊    
 
http://www.books.com.tw/products/0010763045

## 1. 概述 :

### 視覺化 :
* 增加溝通效率
* 進行狀態簡明
* 閒置期/意外期強烈
* 其他注意事項 :
  * 盡量先從物理看板先學會流程, 和做完實作了解自己真正的實際需要,  
    再進一步微調, 然後視情況電子化
    
### WIP :
* 同時執行數量的監控
* 過多會傷害效率
* 過少會造成人員閒置

### 指標 :
* 閒置期

### 特權 Task :
* 安排
* 對應的壞處




## 開始實作 :

### 定義工作階段 :
* 決定團隊產品的 開始, 完成
* 定義一項工作的開始到完成所需要的各個階段
* 其他注意事項 :
  * 不可一人決定看板階段的名稱, 需重複討論簡單明瞭的階段名
  * 如 : Scrum 的階段名 'Story', 'TO DO', 'DOING', 'DONE'
 
### 便條紙 :
* 關鍵且易懂的敘述
* 其他追查用的 Style : Tracking Number, Date
* 工作者圖示
* Highlight 受阻項目
* Color Code :
  * Bug
  * 功能需求 (Light)
  * 維運工作 (Medium)
* 進度指示器
* 情緒

### WIP :
* 平均每個工作的週期 =  $N_{WIP}$ $/$ $(單位時間工作項數)$
  * 假設一個週期兩週14天, 完成的數量若定義為工作數量且在週期內為 10, 執行的時候 WIP限制為 3 .
  * 則平均每個工作週期為 $3 / (10/14) = 4.2 天$
* Context Switch :
  * 增加時間成本
  * 增加風險
  * 在完成量不變會增加工作數量
  * 且降低品質與動力
* WIP 限制的考量是 工作 vs 人員 的閒置
* 視覺化 WIP 的調整與運作中是否失控
